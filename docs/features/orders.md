# Orders & samples

## Purpose

Trade execution after trust **or discoverable catalog**: place and fulfill **orders** (standard or photo) and request **samples**. **Returns are not in the product.** Shop issues go through **1:1 chat ＋ complaint**. **Discoverable** designs/collections (Followers with allowed follow, Selected list, or Connection for trade) can be ordered without inventing a second gate; legacy Everyone/Connections rows behave as Followers. Photo orders and samples without a discoverable product still need a connection.

Sellers can fulfill **partially**: quote fewer qty / skip designs, confirm or decline lines, and split dispatch across multiple LRs.

## Who uses it

Buyers place / accept quotes; sellers quote, confirm, and dispatch (full ship closes as **Dispatched**). Samples and returns are managed from the **Orders** tab (unified feed + type filter).

## User flows

Bottom nav **Orders** shows a teal count (same pill as Chats) for how many tickets **Need you** — the same rows as the Pending list left accent (orders, samples). Hidden at 0; the **exact** number (not 9+). Tap opens `/orders`.

## Business rules

### Order status (rollup)

| Status | Meaning |
|--------|---------|
| `requested` | Pre-confirmation; lines may be `open` or already `declined` from a quote |
| `confirmed` | At least one line confirmed; ready to ship |
| `part_shipped` | Mid-fulfillment only: some qty out, some still open — StatusPill while you can still Dispatch more or Settle |
| `dispatched` | Full ship done — **order complete** |
| `settled` | Seller **Settle order** after qty mismatch — **completed** (StatusPill **Settled · complete**); line qty := shipped so the ticket is whole for the new qty |
| `delivered` | Legacy buyer Mark delivered; lists treat as completed |
| `declined` / `cancelled` | Terminal — timeline ends on this step (no dispatch/settle tail) |

### Line status

## Edge cases / empty states

- Empty list copy follows the tab and Pending / Completed. Buying: **No pending orders yet** / **No completed orders yet**, then **Orders you place will appear here.** Selling names orders from buyers. Others: **Nothing here yet** / **Nothing finished yet**, then **Complaints and applicable samples will appear here.**
- Restricted audience without membership → cannot place trade (`CONNECTION_REQUIRED`). Open (discoverable) catalog lines order without connection — including published designs that are only reachable inside an openable album (not only standalone Explore market posts).
- Quote with all lines “Can’t supply” → rejected; use **Decline order** instead. Untick restores a gray Declined row; sending a rate on it re-opens the line.
- Pack size lives on **each design** (`unit` = order taken in, `dispatchUnit`, `piecesPerPack`). Platform default: **order in sets**, **price / billing per pc**. **How many / Place order:** every line is **name only** (no Piece / Metre / Set beside it, no Sets caption, no per-line Total). Every order design list uses shared `OrderUnitGroups`: always a header **`Order in Sets`** / **`Dispatch in Pcs`** (one unit or mixed). Confirm / quote / Settle use **Order in**; Dispatch uses **Dispatch in**. Same grouping on How many, builder, **Edit order / Edit inquiry**, ticket, and those sheets. Completeness: `2026-10-20-how-many-unit-groups-completeness`, `2026-10-21-edit-order-how-many-chrome-completeness`, `2026-10-21-order-ticket-unit-chrome-completeness`, `2026-10-21-order-unit-chrome-completeness`. Ticket mill-bill **Total** (shared `OrderUnitTotal`): group units (set/box) convert when rate unit differs (`100 sets = 100 pcs`); pc/mtr never convert. Blank or cleared pcs-in-set (empty/0 in 1 set contains → piecesPerPack null) → no conversion for that family (`N sets`). **+No pcs in a set** when Total already has a billed ₹ **and** remaining pack lines cannot bill (toggle rings those rows). Sets-only all-blank pack with no ₹: no cue — understood, not given. Mixed units with blank pack next to billed pcs still cue (All is not the whole ticket). Mixed pack bills only billable lines (same as missing rates — do not wipe the family ₹). Missing rate still bills the rest; **+Missing rates** only when Total already has a billed ₹ (All when mixed) — same +extra language as leftover. All-blank rates: no cue. Mixed = one qty+₹ row per order unit, then **All** when every family can bill. No Ship / Balance totals. How many / Edit footer stays one lump ₹. Completeness: `2026-10-21-ticket-unit-bill-totals-completeness`, `2026-10-21-ticket-total-missing-rates-completeness`, `2026-10-21-ticket-missing-rates-plus-completeness`. Quiet line is **₹/unit** (`₹1,290/pc`) — never a bare rupee or silent per-set `rate × pack`. When pack sizes on the sheet differ, that line is **`₹… · 1 set = 20 pcs`**. No rates-jargon banner. Missing pack size (set/box/bundle blank; not dozen) → no piece conversion (they settle in chat); footer is sets only. Footer is **one row per unit family** (`80 sets = n pcs`, `70 mtrs`) — mixed units stack; never hide natives. ₹ in the footer only when every counted line is billable. **Billing:** when pack size known or obvious (dozen=12), line/order/How many/quote money = `qty × packSize × rate`; blank pack size → no dispatch conversion and no ₹ total for that pack line. Native unit (pc/mtr/than) — qty and rate stay in that unit (`qty × rate`). Order detail: title is the design **name** (SKU only when name was blank at create). Ticket facts are name only — no **per mtr** / **Set · N** under the name. Ticket compact/detail Qty is the number only (`10`); the unit noun lives once on **Total**. Mixed units restack under **Order in Sets** / **Order in Mtrs** (always, even one family). Under the list, mill-bill **Total** (`OrderUnitTotal`) converts a group unit when the rate unit differs (`100 sets = 100 pcs`); pc/mtr never convert. ₹ is right-aligned on that row when the family can bill. Line **Bill** stays left under the Bill label (same as Qty / Price — not a second right-edge). How many / Edit sticky footer still converts (`80 sets = n pcs`). Price stays empty on that row (do not sum rates). After confirm, Ship / Balance stay on the design only — Total does not copy those columns. Completeness: `2026-10-21-ticket-total-mill-bill-completeness`. Ticket lines always keep Qty · Price · Bill — missing rate leaves Price and Bill empty, never collapses to two columns. How many / Edit keep qty left · ₹ right in the sticky footer. No **Billing** row above the items. Mill **Send** qty is a bare number, so that grid still shows sold-as. Completeness: `2026-10-21-order-ticket-unit-chrome-completeness`, `2026-10-21-order-ticket-billing-footer-completeness`, `2026-10-21-order-ticket-bill-column-total-completeness`, `2026-10-21-order-ticket-total-row-completeness`, `2026-10-21-ticket-qty-number-completeness`. Action sheets (quote / confirm / dispatch / settle / amend) do not repeat `per mtr` under the name — Qty is the order unit only. **Packing slip:** qty in sets and dispatch units when pack size known; total e.g. `Total 80 pc and 20 sets` (omit dispatch part when any blank). Order lines snapshot unit, dispatch unit, pack size, and rate. Completeness: `2026-10-20-order-sheet-density-completeness`.
- Partial ship sets status `part_shipped` until fully out (`dispatched`) or **Settle order** (`settled`). After Settle, StatusPill is **Settled** (qty rewritten); Part shipped stays only as earlier Timeline rows.
- Mark delivered retired for the happy path; full ship closes as `dispatched`.
