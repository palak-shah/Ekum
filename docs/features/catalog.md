# Catalog (designs)

## Purpose

The **design library** is first-class: create, edit, publish (live on Explore for the chosen audience), and **Delete** (soft `archived`). Designs sit in [collections](./collections.md), including the company’s **General Collection** when they have no qualifying pack/catalog membership. New designs come from **You → Designs ＋** (Add designs) or collection photos. Unassigned designs sit in **General Collection** (leftover bouquet — not an order pack).

## Who uses it

Sellers (selling enabled). First publish requires consent; then `canPublish` stays on. Entry via **You** (library on the page — Designs is the library), Home **My designs** (when selling; `/catalog` opens You), or bottom-nav **＋** (sell+upload → **Collection** sheet: **Create new collection** or **Update existing collection** → You Collections). **＋** never a dead tap: buy-only → Orders; otherwise a why-line toast. **You → Designs** has a trailing filled **＋** (accent square, right of the tabs) that opens Add designs. Hide while Selecting or Bookmark. No upload cap → why-line toast. Collections / Catalogs keep **New collection** / **New catalog**. Designs **⋯ / Select** always shows when designs are selected (Add before Hide / Delete). The verb on You Designs and General Collection is **Add to collection / catalog**. Regular album is **Add to other collections**. Catalog-exclusive designs omit Add (not a disabled row). Sheet lists published and draft albums (Deleted hidden; Find + Select same as You; **Already in** first with every pack this design sits in; multi-select collections; catalogs only for leftovers — one catalog, exclusive). The same ⋯ verb is on a design opened from an owned collection, and on owned album select (after Bookmark). Nav **＋** is not Add designs.

## User flows

### Browse library

1. Open **You** (or `/catalog`, which lands on You) → **Collections** tab by default. Three underline tabs: **Collections · Catalogs · Designs**. **Designs** writes `?tab=products`; **Catalogs** writes `?tab=catalogs` (a tap that omits `tab` stays on Collections).
2. The list **is** published — no **Published** chip. **Find** opens a field with a **filter square** beside it (same as Orders / Explore). The menu is **Draft · Deleted**. Close Find returns to published and clears the query. **Showing Draft** (etc.) + **Clear** while a filter is on. Deleted items stay listable here — **no Restore**. Find still filters **this tab** in place (design: name, SKU, notes, tags, pack names; packs: name, description, tags, **original mill shop names**, and member name / SKU / notes / tags). Typed letters are marked in the visible name. Keep the list until they type — not Explore search. Same find text stays when switching Designs ↔ Collections or Bookmark. **Designs is your catalog only** — curated mill photos are not extra rows there; they live on the pack. Pack photos that are yours: draft pack → **Find → Draft**; after pack publish they stay on Designs. A design tile shows the **name**, then one muted line of collection/catalog names it belongs to (leftover has none) — no SKU, date, or rate. **Find → Draft** tiles get the same quiet **Draft** chip as You collections (the published Designs list stays published-only). Explore / Saved / album tiles stay name-only. A design in several collections is **one** library row. Empty Draft while pack designs are live points at **Show live**. No match: **No designs match** / **No collections match**, not the empty-library line.
3. On You: **Collections / Catalogs / Designs** parent underline tabs; **Find** + **Feed / Grid**. Collections create is **New collection** (list row) or nav **＋**. Catalogs create is **New catalog** (same editor, `?kind=catalog` — **Catalog name** never Collection name; exclusive General Collection picker, Order as whole / Pick and choose; exclusive why-block is warning-soft so it cannot be skimmed; no treat-as checkbox). Catalog editor / album / toasts / errors say **catalog**. Last Feed/Grid choice remembered with album + Bookmark; **Ekum default Feed**. **Feed** matches Explore’s inset photo and shows the **name**, then a muted pack-name line when the design sits in collections/catalogs. A single photo is **4∶5** so a model or full print loses only a little top and bottom — not a short `h-64` crop. **Grid** stays compact (`h-32` / 2-col). **Long-press** a tile → floating **Select all** + **Clear** (this filter) → dock by filter (bottom nav hidden while selecting): **Collections** are a list of published and draft together (**Draft** chip; thumb is the last photo on the newest design). **General Collection** pins first with a **General Collection** badge from `kind` (rename does not change it); no Add/Remove/Delete on that album. Page ⋯ is **Deleted collections** · **Bookmarks** (not row actions). Swipe a row for **More** · **Share**. Row **More** is **Hide Draft / Unhide Draft** · **Delete** · **Order** — no **Repost**, no **Restore**. Select dock is **Share** · **Order** only. **Designs** stay a two-column grid; Find there is **Draft / Deleted**. Designs select ⋯ is **Add to collection / catalog** (hidden when any pick is catalog-exclusive) · **Repost** · Hide · Delete last. **Draft** designs = **Publish** · **Delete**. Deleted designs have no Restore. Order / Curate send **published** picks into traveling Selection (`/selection` with `openOrder` / `openCurate`). **Share** opens the same chat sheet as album Share (no need to open the tile). Header Share stays the shop. Drafts and deleted have no trade verbs. Share / Bookmark stay on **Your selection** (mixed piles). Selecting on My designs does **not** auto-fill Selection. Create/edit screens keep **PageHeader** at the top.
4. Open a published design → shared **DesignSheet**. Under the photo: **item tags** (tag pills) on the left, **rate** on the right; **description** on the next line when there is one. Trade footer + **⋯** with Bookmark · **Edit design** · **Publish** (draft own: from an album, one tap — pack Who, no Explore tile; You Designs / editor still ask Who for an Explore tile) · **Add to collection / catalog** (You Designs / General Collection; omit Add when catalog-exclusive) · **Delete design**. Opened from a regular owned collection, **Add to other collections** then **Remove from this collection**. Catalog album omits Add and uses **Remove from this catalog**. Order / cart / Share toast **Publish first** on drafts. **Edit design** opens the editor. Sticky **Update** · **Visibility** (or Publish) sits on the shared page CTA dock (`BottomTradeDock`, nav hidden); last fields (Size tags) clear the bar. Draft / Deleted tiles still open the editor directly. Back from editor returns to Designs tab. Collection photos still become designs here too.

### Batch add designs

**You → Designs ＋** opens Add designs (`/catalog/products/new`). **New collection → Photos** / album **Add photos** also create designs. Empty published / draft Designs offers **Add designs**. Unassigned new designs sit in **General Collection**. Phone continuous camera or gallery multi-select; desktop file multi-select. Empty dashed CTA: **One photo per design** (why-line: each photo is its own design, not more shots of the same one). Leaving the camera (Cancel, Done, Gallery, back, other tab) **hard-stops** the stream so the privacy LED goes off. Grid heading is **N design(s)** (not “photos”), with a quiet tip: **Tap a design to edit details or add more photos.** Grid caps at **9** with blurred **Load more / +n**. Each thumb gets a session-unique **SKU** (`EK-` + 8 hex — same as Edit design **Reference / SKU**), not the file name; that value is saved as both `sku` and `name`. After a design is created, a second Save/Publish in the same batch skips re-create; if the server still reports the SKU taken (retry after a partial success), the UI says **Designs already added** — not a raw SKU clash. Tap photo → **Update this design** sheet: **Add photos** opens fullscreen camera on phone (Gallery from that chrome) or the file picker on desktop — more photos stay on that design (not new designs); **no per-design photo cap**. The update sheet dismisses while the camera is open and returns after **Done** / **Cancel** so the viewfinder is not covered. Solo add (not in a pack) has the same **Category** dropdown as New collection (full catalog; Settings deal-in of exactly one is pre-selected), then **Item tags** / **Quality / work tags** / **Size tags** typeaheads (used first, official, cap 8; list stays after a pick; Escape / tap outside / empty Enter / keyboard Done closes it). Rate, then **Order and dispatch** collapsed accordion (same as collection; open to set). **1 set contains** keeps **n** and **pc/pcs** together beside the number. **Done** keeps this design’s details when they differ from shared — no **Use same as all designs** on this sheet (that label reads like stamp-all; matching others is the page **Same for all designs** card, or type the same fields). Page details: one design → **This design**; two or more → **Same for all designs**. Primary **Publish N** or secondary **Save in Draft**. One photo ≈ one design; each becomes a single catalog row (`draft` or `published`, never two copies). Single-design editor: `/catalog/products/:id`.

### Edit & publish a design

1. Open design → photos first; **tap a photo** opens PhotoViewer (swipe between shots); **×** removes that photo. **Name** (blank uses the SKU). If the design is exclusive to a catalog (`catalogCollectionId`), only **photos, name, and notes** show — category, tags, rate, Rate per, order/dispatch, SKU, and Publish/Visibility live on the catalog. Otherwise **Rate per** (default **pc**; the unit list follows Category) and one fixed amount (no range; saving clears a stored high rate; Add designs does not accept `1200-1400`). If the design is in a collection that already has a **Category**, that value is read-only. If the collection has no Category yet (or the design is solo), show the Category dropdown. Tags are **Item tags**, **Quality / work tags**, and **Size tags** — the same typeaheads as a collection (suggestions on focus; scroll the list does not pick; tap to add; list stays after a pick so they can add another; Escape / tap outside / empty Enter / keyboard Done closes it). Collection tags append onto the design (union, no duplicates, cap 20); the design’s own tags stay. **Order and dispatch** is the same collapsed accordion as a collection (open to set; **1 set contains** keeps **n** and **pc/pcs** together). **Show details** stays closed until opened: **Reference / SKU**, then notes. Opening it (and Order and dispatch / Who / album-change) scrolls the opened block into view above the dock.
2. Status line under title (tap → Visibility when published). Sticky dock: filled **Update**, then **Publish** / **Visibility**. Leaving with unsaved edits → **Save changes?** · **Save** (keeps what they typed) · **Discard** (last, danger) — Cancel / close stays. Clean form: no prompt.
3. Publish sheet: Who (**Followers** / **Selected** — no Everyone) / rates / forward. Default audience **Followers** (API + DB). Legacy `everyone` / `connections` rows migrate and enforce as Followers. First time: consent. Publish = Explore for that audience.
4. **⋯**: Hide → **Draft**. **Delete** (soft; irreversible). No Restore. Drafting a design that sits in several packs warns that it shows as **Draft** on every album you own; buyers will not see it. Owned album Select ⋯ has the same **Draft**. You Designs Select ⋯ is **Hide · draft**.

## Business rules

| Rule | Detail |
|------|--------|
| Lifecycle | `draft` → `published` → `archived` (trader word **Deleted**). No Restore. |
| Publish = Explore | Solo **Publish design** sets audience + `postedToMarketAt` (Explore tile). **Publish collection** puts the pack on Explore and marks member designs **Published** in My designs **without** separate Explore design tiles (`postedToMarketAt` stays null). Designs tiles show the name plus a muted membership line when in packs. |
| First publish | `consentToSell` grants `canPublish` |
| Rates | Nullable / on request by default. **Add/edit design** is one amount (`rateMax` cleared). **Pack** Rate may still be One rate / A range (`rateMax`). **Pack path** (order unit set/dozen/box/bundle): rate is **per Rate per unit** (`catalogRateUnit`) — independent of **Dispatch unit**. Create label **Rate per {unit}**; browse/How many/orders show `₹…/{Rate per}` (e.g. `/mtr` when chosen while they still dispatch in sets). **Never chosen:** default **pc** when pc is among offered Rate per options; if pc is not offered (e.g. fabric), default to a unit that is offered (typically **mtr**) — never force-insert pc. **Native path** (pc/mtr/than…): rate per that order unit. Orders snapshot `rate` + units including Rate per. |
| Pack size | How they sell lives on **each design**: **order unit** (`unit`) + **dispatch unit** (`dispatchUnit`) + **Rate per** (`catalogRateUnit`) + `piecesPerPack` (contents in one order unit, labeled in Rate per). Collection create/edit stores those on the **collection** so Rate per / Dispatch / 1 set contains reload from pack details, then stamps own members. Changing Rate per does **not** rewrite Dispatch. Platform default (even when Catalog settings never saved): **order + dispatch journey in set**, **rate / billing / “1 set contains” unit per pc** (empty: placeholder `4` + Rate per unit, e.g. **mtr** when Rate per is mtr; placeholder hides on focus; typed `4` reads **4 mtrs**; typed **0** or blank means not given and clears stored pack size (`null`) — no invent leftover). Explore pack cards show collection details **₹rate/Rate per** (e.g. ₹91/mtr), not leftover /pc. If collection details has no rupee, Explore shows the same design min–max as the album (owner always; other shops only when Show rates is visible). Settings can override. ~**20%** niche (e.g. lehengas) set **Order taken in = pc**. On collection create/edit, **changing master category does not rewrite** sell-as units; official cascade tags may prune to the new taxonomy, **custom tags stay**. **Obvious exchanges** stay (e.g. **dozen = 12**). Order qty is in the order unit; dual qty / billing use pack size when known or obvious. Order lines snapshot order unit, dispatch unit, Rate per, and pack size. API create fills `unit=set` / `dispatchUnit=set` when omitted (rate still per pc). |
| Download | `allowDownload` on design (and pack); buyers cannot export when false. |
| SKU | Optional on API; batch add assigns a session-unique `EK-` code and sends it so Edit design **Reference / SKU** matches. Server still assigns if omitted elsewhere. **Blank design name** (You → Add, new pack photos, upload/edit save) → name is that SKU. Typed name wins. |
| Selling presence | Creating products calls `ensureSellingEnabled` |
| Unpublish | Clears Explore post when design leaves published. The pack stays **Published** until they **Hide from Explore**. Explore omits packs with no published members. |
| Unarchive | Not allowed (`NOT_ALLOWED`). Deleted stays under the Deleted filter. |
| Bulk Select | Same visibility sheet for many drafts → publish each |
| Staff audit | `createdBy` / `updatedBy` on product views. **You** library tiles and the collection editor status line show the **date only** (no own name). Saved still may show staff. |

## Edge cases / empty states

- Empty Designs tab (published / draft): **Add designs**. Collection photos still become designs here too.
- Batch session caps (e.g. 120 designs) and parallel upload progress.
- Archived designs are out of the active picker for new collection membership (non-archived only).

## Seed walkthrough

1. As Ravi: **You → New collection** → add photos → save drafts → open one on Designs → **Publish** → Connections.
2. Confirm My Catalog tile shows `Published · My followers` (or the audience chosen) and Explore shows the design for an **allowed** follower (pending asks do not see it).
3. Hide → draft; owner album and You Find → Draft tiles show the Draft chip (not “not on Explore”). Buyers do not see that design.
